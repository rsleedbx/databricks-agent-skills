# SQL Server source behaviors and errors

What happens on a SQL Server source, with the error text as the product returns it. Names and IDs are placeholders (`<slot_name>`, `<schema>.<table>`, `<user>`, `<database>`). Shared behaviors (reading the destination, gateway compute, table limits): [database-source-behaviors.md](database-source-behaviors.md).

| Symptom | Likely cause | Fix |
|---|---|---|
| `PIPELINE_NON_RETRYABLE_ANALYSIS_INTERNAL_ERROR` and `GENERIC_SNAPSHOT_FAILURE`: "STREAM_FAILED ... VIEW DATABASE PERFORMANCE STATE permission denied in database <database>". A small table in the same database ran without it. | Integrated CDC on many tables in one pipeline (450 tables); the setup utility's grants applied | `lakeflowFixPermissions` doesn't grant this. Run `GRANT VIEW DATABASE PERFORMANCE STATE TO [<user>];`, then start a new update: the failed one doesn't retry. |
| `INGESTION_GATEWAY_DDL_OBJECTS_MISSING`: "DDL objects missing on table <schema>.<table>. Execute the DDL objects script and full refresh the table", then `PIPELINE_NON_RETRYABLE_ANALYSIS_CLIENT_ERROR` | Utility 1.5 installed, then 1.7 without the flag (database with a non-default collation) | Run the DDL objects script the message names, then full refresh the table. A rerun of the change-tracking setup with `@CreateDdlSupportingObjects = 1` also passed. |
| `INGESTION_GATEWAY_UNTRACEABLE_TABLE_MODIFICATION`; the update FAILED and the later inserts don't arrive | `TRUNCATE TABLE` on a change-tracking table | Full refresh that table. |
| No error: updates COMPLETE with no error event, and a changed row doesn't arrive | `sp_cdc_disable_table` on a table's capture instance | After any change to a capture instance, full refresh the table. |
| `INGESTION_GATEWAY_CDC_LOG_TRUNCATED`: "CDC log truncated, full refresh required" | Capture-instance name in a different case from its table (case-insensitive database) | Take the exact name from `SELECT capture_instance FROM cdc.change_tables;`, then full refresh the table. |
| Rows whose seventh fractional digit changed don't arrive, and the update COMPLETES. With a `datetime2(6)` cursor on the same data, they arrive. | Query-based cursor on `datetime2(7)` | Use `datetime2(6)` or lower until the case is checked. |
| Error 8649 at compile; nothing runs | `query governor cost limit` set for the gateway's login | Remove or raise the limit for the login, then count after `SNAPSHOT_COMPLETED`. |
| A keyless snapshot ends early; the update COMPLETES short with no error event | Resource Governor `REQUEST_MAX_CPU_TIME_SEC` set for the gateway's login | Remove or raise the limit for the login, then count after `SNAPSHOT_COMPLETED`. |
| Schema Exploration still reports `Found <n> table(s) in the connection` | Pipeline scoped to one schema of three | Discovery reads the whole connection; the scope limits the ingestion reads. Scope the pipeline's tables to limit what's read. The count also includes every other database the login can see in the container. |
| Nothing changes; updates keep working | `VIEW DATABASE PERFORMANCE STATE` revoked while the login holds `VIEW DATABASE STATE` | `VIEW DATABASE STATE` implies it. To remove both, revoke `VIEW DATABASE STATE`. |
| The gateway logs a schema change; the row written after it never arrives. No error. | `VIEW DATABASE STATE` revoked, then a column added | Keep `VIEW DATABASE STATE` on the ingestion login, and check new rows after each schema change. |
| Each table, busy or idle, is read about every 17 s; changes lag the commit by up to about 20 s. Every change arrived. | Change tracking with many tables in one gateway (150 tables) | Measure at your table count before splitting tables over gateways: insert a new key per change, since change tracking returns one change per key between reads. |
| It resumes each table from its position, with no re-snapshot; the rows written meanwhile arrive in the next ingestion update. `RESETTING` shows in every gateway update. | Gateway pipeline stopped and started during CDC (5 minutes) | None needed while the source keeps the changes for the time stopped. |
| The next update COMPLETES with the column; earlier rows are NULL in it | Column added after the first load (standard CDC or change tracking) | No full refresh is needed. |
| The running update is cancelled ("due to a schema change ... will be restarted"), and a new update starts with cause `SCHEMA_CHANGE` | Column added to an integrated CDC table | No full refresh needed; wait for the new update. |
| The snapshot keeps one row. An update to one copy removes the other copy from the destination. | Table without a primary key, with identical rows | Add a primary key before the first load (not verified). |
| The gateway logs a WARN that the DDL support objects "may be safely removed". The update still completes. | Change tracking with `@CreateDdlSupportingObjects = 1` | Nothing is needed for the run. |
| Arrives as the hex of its binary: `/1/2/` arrives as `5B40`. No warning. | `HIERARCHYID` | Not converted to the path text; check the destination against the source. |
| Arrives as WKB binary, with the SRID dropped | `GEOGRAPHY` | Keep the SRID in another column if it matters (not verified). |
| Arrive as microsecond timestamps, with the 100 ns digit dropped. `DATETIMEOFFSET` becomes UTC and loses its offset. No warning. | `DATETIMEOFFSET(7)`, `DATETIME2(7)` | Keep the offset or the 100 ns digit in another column if it matters (not verified). |
| `TIME(7)` as a string with all 7 digits; `MONEY` as `decimal(19,4)`; `UNIQUEIDENTIFIER` as an upper-case string; `XML` and `SQL_VARIANT` as strings; `ROWVERSION` as binary | `TIME(7)`, `MONEY`, `UNIQUEIDENTIFIER`, `XML`, `SQL_VARIANT`, `ROWVERSION` | None needed. Check the destination types against this list. |
