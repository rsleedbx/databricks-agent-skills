# Oracle source behaviors and errors

What happens on an Oracle source, with the error text as the product returns it. Names and IDs are placeholders (`<slot_name>`, `<schema>.<table>`, `<user>`, `<database>`). Shared behaviors (reading the destination, gateway compute, table limits): [8-database-source-behaviors.md](8-database-source-behaviors.md).

| Condition | Error or symptom | What to do |
|---|---|---|
| `source_catalog` missing from the gateway | `NO_CONNECTION_PARAMETER`; the message names the literal `CDB$ROOT` | Set `connection_parameters` to `{"source_catalog": "<CDB service name>"}`, the base service name that `lsnrctl status` lists. The literal `CDB$ROOT` fails with `INGESTION_GATEWAY_CONNECTION_ERROR.SOURCE_AUTHENTICATION_FAILURE`: "Oracle service name 'CDB$ROOT' is invalid". A `source_catalog` under `gateway_definition` is dropped by the CLI ("unknown field: source_catalog"). |
| Supplemental logging added to a table (checked in `DBA_LOG_GROUPS`) | `INGESTION_GATEWAY_CDC_NOT_ENABLED`: "Primary Key supplemental logging is not enabled on this table." Updates kept failing after the change; after a restart, other tables reported it | Restart the gateway after each logging change, then start the update. |
| Connection through a PDB's service name | `INGESTION_GATEWAY_INTERNAL_ERROR`: "The Ingestion Gateway has encountered an internal error and cannot recover". The pipeline events don't show the cause. Direct SQL on that service fails at `DBMS_LOGMNR.ADD_LOGFILE` with `ORA-65040`. | Connect with the CDB's service (the connection's `service_name`, and the gateway's `connection_parameters.source_catalog`), and name the PDB in each object's `source_catalog`. |
| User without `CREATE SESSION` | `ORA-01045: Login denied` at connection (`INGESTION_GATEWAY_CONNECTION_ERROR.SOURCE_AUTHENTICATION_FAILURE`) | Grant `CREATE SESSION` first. Missing privileges show up in this order: session, then the view grants, then table `SELECT`. |
| User with `CREATE SESSION` only | `ORA-00942: table or view SYS.V_$DATABASE does not exist` ("Could not fetch database name") | Grant the full list in the next row. |
| Table without `SELECT` | `GENERIC_SNAPSHOT_FAILURE`: "Snapshot failed for table <catalog>.<schema>.<table>", with `ORA-00942` | Grant `SELECT` on the table. None of the three cases above reaches the missing-privilege list, so check with `VALIDATE_SETUP`. |
| Grants lack an object the validator checks | `INGESTION_GATEWAY_CDC_NOT_ENABLED`: "Requires following permissions : SELECT on <object>, SELECT on <object>, ..." | Grant each object by name: `EXECUTE` on `DBMS_LOGMNR` and `DBMS_LOGMNR_D`, `SELECT` on `DBA_SEGMENTS`, and `SELECT` on each `V_$` and `GV_$` view listed. `SELECT ANY DICTIONARY` doesn't satisfy the check. |
| Restricted user with `SELECT` on a few tables | Schema Exploration finds `0` tables; the update stays `INITIALIZING` with every snapshot `SCHEDULED` and no error event. An all-visible user on the same database finds the full set. | Apply the full grant list (a user without `SELECT ANY DICTIONARY` needs about 45 more view grants), then check that exploration finds the tables before starting the update. |
| Archive logs removed before the gateway reads them | `ORACLE_ARCHIVE_LOG_FILES_UNAVAILABLE`: "... Please perform full refresh on all destination tables mapped to catalog <catalog> ..."; LogMiner may report `Specified Log not in dictionary` or `No complete archived dictionary found before SCN: <scn>`. The update can still COMPLETE with its flows failed. | Raise the recovery-area retention (`db_recovery_file_dest_size`, `db_flashback_retention_target`). Full refresh the named tables, and read the flow events rather than the update status. The removal affects every gateway on the container: another gateway there can go to `INGESTION_GATEWAY_INTERNAL_ERROR` ("cannot recover"). |
| A table with an `XMLTYPE` column, in CDC | `TABLE_SKIPPED_DUE_TO_UNSUPPORTED_COLUMN_DATA_TYPE`: "Table contains unsupported column types: XMLTYPE. Oracle LogMiner skips the entire table when any column has these types". The table gets no snapshot, and the update stays `RUNNING` with its snapshot `SCHEDULED`. | Remove the table from the pipeline. Splitting the XML out isn't tested. |
| `NUMBER` with no precision or scale | Lands as a string with the exact digits (`1234.5678`), not as a decimal | Cast in queries, or declare a precision and scale on the source (not verified). |
| `TIMESTAMP(9) WITH LOCAL TIME ZONE` | Lands as text with the zone name inside: `2026-10-25 12:00:00 Etc/UTC.123456789`. `TIMESTAMP WITH TIME ZONE` lands as a timestamp in UTC. | Parse the text, dropping the zone name. |
| A source table dropped while its pipeline runs | After changes reach the gateway, the update fails at analysis: `[INGESTION_GATEWAY_TABLE_DROPPED] Source table <catalog>.<schema>.<table> has been dropped on source`, and "A new pipeline update will not be created". Every table in the pipeline stops. | Remove the dropped table from the ingestion pipeline. The first update after the drop can still complete. |
| Common user without `SET CONTAINER` and `CONTAINER_DATA=ALL` | `MISSING_TABLE_IN_SOURCE`: "No catalog or schema was found for replication. Please check your filter file". The gateway finds no tables. | Grant the two multi-container privileges from the grant list, then restart the pipelines. |
| Source password changed, and the connection keeps the old one | `INGESTION_GATEWAY_CONNECTION_ERROR.SOURCE_AUTHENTICATION_FAILURE`: "ORA-01017: invalid credential or not authorized; logon denied". The retries repeat it. | Update the connection with the current password, then start an update. |

Tested 2026-10-25 on Oracle Free 23.26.3. The new rows: tested 2026-10-26 on the same version.
